Rules the whole core keeps

Plugins have no power of their own. Every plugin runs in a Chromium worker or frame and can only ask the capability gate. The gate is the reference monitor: always in the path, out of reach of plugins, small enough to check.
The daemon holds all power. It is Electron's main process. The hidden renderer and editor windows only get what the daemon grants them.
Mechanism in the core, policy in plugins. Leases, the watchdog and git all follow this split: the core enforces, a core plugin decides.
Security stays on until you approve otherwise. Every security switch needs a Windows Hello or Touch ID approval, lives per machine and shows a banner while off. A guard that crashes fails closed.
Only hetu's service writes the security state. It runs under its own Windows account, so a program running as you, not elevated, can't edit, replay or delete the state, and every change needs your Windows Hello gesture. What's left is deception: a program that injects code into hetu could show you one change and ask for another. That is an accepted risk, since no app on one PC can show you something such a program can't also draw. Elevated programs are out of scope.
Start narrow, widen on demand. The capability list and the editor API only grow with a core API version. Adding breaks nobody, removing breaks every plugin.
