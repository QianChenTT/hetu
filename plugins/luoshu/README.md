The luoshu, an install plugin whose host half serves `luoshu.read`, `luoshu.write`, `luoshu.remove`, `luoshu.move` and `luoshu.list` on the notes folder the human picked, and publishes `luoshu.changed` for each of its writes and `luoshu.outside` for a save made elsewhere

- **prepare** turns the path the caller wrote into the canonical one with `core/lib/canonical.ts`, which refuses a bad spelling `invalid` and a link or junction out, `.git` by any name, a dot file or dot folder at any depth and hetu's own folders `not-granted`. A dot name counts as the caller wrote it and as the disk resolved it, so a link or junction into `.obsidian` and the 8.3 short name of a dot folder are refused too, on both ends of a move. It holds the lock on the path's key until perform or release, so no other hetu write to that name runs in between
- **a write** checks the version it was made against under the lock: none for a new note, else the hash of the bytes read. The bytes go to a dot temp file beside the note, then a rename over it, so a crash leaves the old note or the new one
- **a remove** hands the note to the bin the runtime gives the luoshu, only at the version the remover read, the hash of the bytes, so a call with none or with an older one answers `stale` and a plugin that can write a note and can't read it can't bin it. A bin that refuses fails the remove and the note stays, and with no bin a remove answers `unavailable`
- **a move** takes the locks of both ends in key order, so two moves the opposite way round never wait on each other. It never lands on a name that exists: a hard link at the to end fails if anything is there, then the from end is unlinked. A move that only changes the spelling of the note's name is one file under one lock, renamed in place. Both ends' folders are resolved again just before the disk changes, so a folder swapped for a link since prepare is refused
- **a listing** answers up to a page of file paths in name order under a folder, past every dot file and dot folder at any depth (`.git` and the dot temp files a write makes among them), links and hetu's own folders, with the last name as `next` when more remain. The walk leaves dot names out itself, since the carrier's canList passes every name with the gate off by the human. The carrier keeps the names the caller may list or read, and no listing carries a version
- **the watcher** is `fs.watch` with `recursive`. A path quiet for 150 ms is hetu's own write when its bytes hash as the last write hetu made there, and `luoshu.outside` otherwise. A path canonical refuses, a dot path included, publishes nothing
- with no folder picked every call answers `unavailable`

`src/luoshu.ts` holds the logic and `src/host.ts` is what the loader imports: the plugin, the `provider` role and the `luoshu` role, whose `open` the loader calls with the folder when the plugin is ready and each time `luoshu.set` applies
