One package per plugin with one manifest and one identity. Its entries say where each half runs: `worker` in a hidden renderer and `frames` in a window. Install plugins may also have `host` in the main process and `page` in a window. The manifest names `requires` and `provides`, install plugins also `guards` and `node`. The first host-level plugins are gate, capabilities, watchdog, storage, luoshu, leases, history, exec, net and http. The event log is the core's own. Hidden marks runs in-page, compiled into the editor page from the install. CodeMirror is the editor window's own, no plugin. Git, search, the file explorer, artifacts and the layout run sandboxed

`search/` is first-party search and `layout/` hetu's own layout, both built on `@hetu/sdk` and tested on its fake core, the layout on its fake drawer too. A plugin may declare `views` drawn as trees or frames and a `theme` of token values in its manifest. `gate/`, `capabilities/`, `storage/`, `luoshu/`, `history/` and `exec/` are install plugins with host halves only. `history/` keeps hetu's own record of notes in a repo under the data folder, written with git plumbing that never takes the notes folder for a work tree. `exec/` runs only the exact argument arrays a plugin declared, gate off included, in an environment built from empty
