History, an install plugin whose host half serves `history.commit`, `history.log` and `history.read`: hetu's own record of notes, in a repo hetu owns. It needs `git` on the machine. With none its start throws, it reads as failed and calls answer `unavailable`

**Why a repo of its own.** git reads config, hooks, filters and nested repos from the folder it works in, and each can name a program to run. A notes folder can come from anywhere, so git is never pointed at it:

- the repo lives under the data folder, at `host/history/<key>/shadow.git`, one per notes folder, the key from the folder's real path. It is made with no template, so it has no hooks folder
- git runs with `--git-dir` alone and never a work tree, from an empty folder of history's own. Only plumbing: `hash-object`, `read-tree`, `update-index`, `write-tree`, `commit-tree`, `update-ref`, `rev-parse`, `rev-list` and `cat-file`, and the repo is made once with `init --bare --template=`
- a note's bytes are read by history and reach git on stdin, so git is given no path in the notes folder and applies no filter, line ending or encoding change to them. What comes back from `history.read` is what the file held
- the environment is built in `core/lib/clean-env.ts` and holds nothing of hetu's own: no system or global config, a home with nothing in it, no prompt and a PATH of git's own folder
- every call carries `--literal-pathspecs`, so a note named like a pattern matches only itself, and overrides `core.fsmonitor` and `core.hooksPath`, so a config or hook edited into the repo itself doesn't run, and every call sets `protocol.allow=never` and `GIT_NO_LAZY_FETCH`
- git comes from the PATH by its real absolute path, never from the notes folder or the data folder

**The calls**

- **prepare** turns each path into the canonical one with `core/lib/canonical.ts`, as the luoshu does, so the gate decides on the name the note really has. A dot file or dot folder at any depth, `.git` among them, a link out and hetu's own folders are refused there. A path spelled with no dot that leads to a dot name through a link, a junction or an 8.3 short name answers as the same name missing would
- **`history.commit`** records the notes at up to 64 paths as one commit. A path with no note is recorded as removed. Each note's folder is looked at again just before the note is read. One swapped for a link or a junction since prepare refuses the commit `not-granted`. One that only changed case since, whose path resolved again from the caller's spelling gives the key prepare took, is read and recorded under that path once the call's judge says the gate allows it, else the commit is refused `not-granted`. Once a note is open, its path is resolved again from the caller's spelling and the file at it compared with the one opened (`named` in `core/lib/canonical.ts`), since the open follows a note made under another case of the last name while the commit waited, which the look at the folder never sees. The note is recorded only under the path judged or one the judge allows, else the commit is refused `not-granted`. A note replaced at its name since the open is opened again, three times at most before the commit answers `stale`. Nothing changed answers `{ commit: null }`. The committer is the caller and the author the client the call was made for, when it names one. A file over 16 MiB, or notes that together weigh over 64 MiB, refuse the whole call with `too-large`
- **`history.log`** lists the commits that changed one note or anything under a folder, newest first, 50 unless the caller names up to 200. A commit that changed only paths with a dot segment there, which only a build from before dot names were refused could have made, is left out. The commits after the first page are read 200 at a time, so a long run of them costs a page for every 200. A log past its deadline stops paging and answers `timeout`
- **`history.read`** gives one note's text at a commit with the hash of its bytes, the shape `luoshu.read` answers. A file that isn't UTF-8 is stored exactly and refused here with `not-text`. A restore is the caller writing the text back through `luoshu.write`
- calls run one at a time, since the repo has one index
- the manifest requires the luoshu, so with the luoshu off history waits and reads no note

`src/history.ts` holds the logic and `src/host.ts` is what the loader imports: the plugin, the `provider` role and the `history` role, whose `open` the loader calls with the notes folder when the plugin is ready and each time `luoshu.set` applies. `test/a11.test.ts` shows each planted program firing under plain git in the notes folder and not through history
