Exec, an install plugin whose host half serves `exec.run`: one command, as its argument array, for a plugin that holds an `exec` item. A command runs as the user, outside every wall hetu has, so this is the one grant that leaves hetu's model. What exec holds a command to:

- **the exact list.** The caller's whole argument array has to be one its `exec` items list, argument for argument. Nothing is matched by joining words and nothing is a pattern. The gate judges the same array when it is on. This check is exec's own, against a view of the grants the loader renews with every change, and it holds with the gate switched off
- **any command** is the human's switch for one plugin. It lifts the list for a plugin that holds an `exec` item and gives nothing to one that holds none
- **only plugins.** A window and a content frame hold no `exec`
- **no shell.** The program is found on hetu's PATH by a bare name or taken by an absolute path, then run by its real path with the arguments as they are. A `.cmd` or `.bat` file is never run, since a shell would read it
- **an environment built from empty** in `core/lib/clean-env.ts`. A command gets the variables its item names, each with the value hetu itself has, and nothing else. A name that makes a program load code (`NODE_OPTIONS`, `LD_PRELOAD`, every `GIT_` variable and their kin, listed in `core/api/exec.ts`) is refused in a manifest and again here. On Windows a process start always carries eleven variables, so the base sets them on purpose with a PATH of System32 alone
- **write-then-run.** Neither the program nor any argument may name a file in the notes folder or in hetu's data folder, where a plugin could have written it: an absolute path, what follows an equals sign, a file URL, a relative path that climbs out of the working folder and a path that reaches one of them through a link are all refused. Each run gets a new empty working folder under `host/exec/` in the data folder, removed when the command ends, so one command can't leave a file for the next. **The limit:** a path inside a longer string, such as code handed to `-c`, or one a program finds on its own is not seen. The approval screen shows every command and names the programs that run other programs
- **limits.** No input, 1 MiB each of stdout and stderr with `truncated` past that, the call's deadline as the time limit, answered `timeout`, and four commands at once a caller, answered `throttled` past that. A command still running when exec stops is ended. A program a command started itself is not

`src/exec.ts` holds the logic and `src/host.ts` is what the loader imports: the plugin, the `provider` role and the `exec` role, whose `stateChanged` the loader calls with the view when the plugin is ready and with every change after
