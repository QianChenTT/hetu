The contract every part of hetu shares: data, schemas and pure functions with no Node, no DOM and no I/O. `tsconfig.json` loads no types and only the es2024 library, so a Node import or a DOM global fails the typecheck. A test checks the imports too

- `envelope.ts`: the messages on a port, requests and replies, the refusal and reason codes and the callers. The topics core modules publish (`moduleTopics`), each with who hears it and the fields it carries beside its path, `lock.changed` its `lockFields`. Also the field a root plugin sets on its calls (`label`) and its grant key (`grantKeyOf`), the field up to its first `#` or the whole field when it holds none, which a pair's grants, asks and revoke are keyed by so each session of one client shares the client's grants. A field starting with `#` is refused
- `version.ts`: the envelope's version, apart from zod so the SDK loads it without the schemas
- `changes.ts`: the change kinds a security request carries, whether each widens, narrows or destroys data (`changeEffect`) and what the human types to switch protection off (`mustType`)
- `describe.ts`: the core's own words for each change, which the trusted window draws above Confirm. A connect with no redirect reads as a program on this computer reaching hetu over the local pipe
- `trusted.ts`: what the trusted page shares with the core, apart from zod: the input delay and how a capability reads
- `capabilities.ts`: the fixed capability list with the install-only types marked and the types a pair may hold (`pairTypes`), which the gate and the ask for a pair's items read
- `scope.ts`: the scope grammar, the path matcher and the check for characters that could hide on a screen. The matcher matches no path with a dot segment
- `paths.ts`: `pathProblem` and `actionPathProblem`, the checks for a path as an action takes it, with `MAX_SCOPE_LENGTH`, apart from zod so the SDK hands `actionPathProblem` to plugins. `scope.ts` and `actions.ts` hand them on where they always were
- `names.ts`: `isDotName`, the one check for a segment no note path holds, with `withoutIgnorable` and apart from zod so the SDK hands `isDotName` to plugins
- `manifest.ts`: `hetu-plugin.json` from the install and from the plugin folder, and `supportsApi`: this core's major or an older one every major since only added to (`apiChanges`), with no type in the manifest added, removed or reshaped since
- `ids.ts`: plugin ids and names, reserved ids, the namespace table that gives every namespace the core keeps its server (the part handed to the router under that name and the route to it), the provider ids read from it, the guard ids with the lock guard, whose deny answers `locked`, the core modules that judge yes or no (`judgingModuleIds`, which with the guards are `failSafeControls`, the one list the fail-safe at start covers) and the ones whose answer is no plain yes or no (`guardingModuleIds`), all of them the security controls, and the door's id (`doorId`) with the Node built-ins its build may import (`doorNode`), and the host each plugin's frames load from, `<id>.views` with each `_` written `--` (`viewsHost`, read back by `frameOwner`)
- `windows.ts`: what each window holds
- `limits.ts`: the limits and the longest delay a timer takes, past which no time constant may be raised
- `actions.ts`: the core actions with who may call each, which the trusted window may send inside its input delay as reads and which name a live call, the bus's actions with what the bus does with each, the provider actions with the capability each is checked against and the role actions (`door.handle`) with who may call each and the item its one holder holds, each with its argument schema. `ActionArgs` and `ActionResults` type what the SDK's calls take and answer. `StoppedMode` says why hetu stopped, `START_HUNG` the reason for a control whose start marker the run before left
- `classes.ts`: the grant risk classifier's interface: the table it is handed at every class change (`ClassTable`), the answer it gives (`ClassAnswer`, a `ClassVerdict` for each plugin the change moves) and the shape check the core runs on every answer (`checkedAnswer`), with the highest class a class not known counts as
- `policy-jobs.ts`: what the router asks and hands on: the plugin table with the one holder of each role (`holderOf`), the gate, guard and provider interfaces, `Call` with the signal it carries into perform, the view of a live call (`LiveCall`) and the gate's time per caller (`GateTime`), the pair a chain under a plugin root carries (`Pair`, keyed by the grant key of its field), the names a commit carries (`signatureOf`), which history and the SDK's fake core share, `Access`, `Decision`, `GuardCall`, the policy job and plugin states, the audit record, the class names, `Opening` and the `LuoshuRole`, `StorageRole`, `HistoryRole` and `ExecRole` the plugins manager calls
- `editor.ts`: the editor bridge's verbs and what each needs, the mark and change shapes, key bindings, `parseBridgeCall`, replies and events. `linkAt` picks the link mark a Ctrl+click, Cmd+click on macOS, lands on, the smallest range holding the character and none on a tie, for the drawer and the SDK's fake alike. The link mark and `editor.link` were added without a major bump
- `ui.ts`: themes, the style list, the tree node and its operations (`applyOps`), the image node naming a note by a path whose extension is one of `imageTypes` (png, jpeg, gif, webp, avif, bmp and svg), added without a major bump, the ui verbs (`uiCall`, `uiNeeds`), `parseDrawerCall`, `LayoutView`, `LayoutState` and `UiEvent`
- `ui-limits.ts`: the caps on what plugins draw, apart from zod
- `exec.ts`: the caps for `history.*` and `exec.run`, `envNameProblem`, `loadsCode` and `commandKey`, apart from zod
- `storage.ts`: `quotas` and `spaceOf`
- `measure.ts`: `measurePlain`, apart from zod
- `rate.ts`: the per-way message counter, the text budget and `weigh`
- `plain.ts`: the plain data check for values the core passes on unread
- `frozen.ts`: the frozen tables with no prototype that the core looks keys up in, apart from zod so the limits load without it
- `pipe.ts`: `pipeName`, the local pipe the door serves and the shim connects to, one a user: a named pipe on Windows and elsewhere a socket in a folder of the user's own under `/tmp`
- `plugin-version.ts`: the manifest's version grammar (`pluginVersion`) and the version order (`isNewer`)
- `lifecycle.ts`: the lifecycle messages on a port, `init`, `deps`, `ready`, `stop` and `stopped`, with the fixed reasons a plugin hears as `lastStop`
