The updater, in main: it looks at hetu's latest full release on GitHub for an update file signed with the publisher's key. A draft or a prerelease never reaches it, since GitHub's latest is the newest full release. Only a locked build checks, so a run from the source and the unlocked build the end-to-end tests drive never reach the network for it

- `check.ts`: one look (`checkLatest`). It asks the API for the latest release of `QianChenTT/hetu` through `core/backend/lib/github.ts`, fetches `hetu-update.json` (64 KiB at most) and `hetu-update.json.sig` (the 64 bytes `crypto.sign` gives, unencoded) and checks the signature with Node's `crypto.verify` against the key in `key.ts` before a byte of the file is read. Only then is the file parsed, once, by `parseStrict` and its schema: `version` as `x.y.z`, `file` as one name ending `.exe` with no folder, `size` up to 1 GiB, `sha256` as 64 lower case hex digits and `released` as ISO 8601 in UTC. A field it doesn't name is ignored and a key written twice refuses the file. The signed version against the running one, part by part as numbers (`versionParts`, `compareVersions`): higher is `found` with the installer's download link when the release holds the signed name, equal is `current`, lower is refused, so an old signed file replayed never passes and no downgrade is offered. A release with the update file and no signature is refused as a bad signature. No full release, no update file, the network, the rate limit, the time and byte limits and a link off GitHub's hosts answer `failed`, quietly. The release page is built from the signed version (`releasePage`), never from the API's answer
- `key.ts`: the public key as PEM, the one constant that decides what hetu installs. It sits in `main.js` inside `app.asar`, which ASAR integrity covers
- `timer.ts`: when the checks run (`CheckTimer`): once after `core.ready`, then 7 days (`CHECK_EVERY_MS`) after each check ends, never in a build that isn't locked and never while the switch is off. Switched on again it checks at once. Node's timer is unref'd, so it never holds hetu open
- `updater.ts`: `createUpdater`, made by `core/backend/main.ts` once the core is wired and told `ready` when the editor window opens, never in the stopped mode. It holds the last check's state for the trusted window (`state`), checks on demand whatever the switch (`check`, joining a check under way), takes the switch (`switchChecks`) and stops the timer and any check under way on Quit (`close`). A refused update is the core record `update.refused` with its `reason` (`signature`, `format` or `version`) and the signed `version` when one was read. A quiet failure is a line on stderr and nothing more. `changed` tells whoever shows the state that it changed
- `header.ts`: its door, the state, the reasons and the 7 days

It imports `node:crypto` and the GitHub fetch from the backend's `lib`, nothing from another part's folder. Its tests are in `core/test/updater-check.test.ts` and `core/test/updater.test.ts`, each with a key pair made for the run and GitHub faked through the injected fetch

Roles: `check.ts` policy enforcer, `key.ts` policy holder, `timer.ts` driver, `updater.ts` service, `header.ts` contract
