Runs in the Electron main process with Node. The core's four parts live here: boot, plugins-manager, router and runtime. The core only checks, places and routes. Policy, disk and process access sit with the core modules bundled into `main.js`: the gate and the grant risk classifier in `policy/`, storage, the luoshu, history and exec in `providers/`, then `flood-control/`, `heartbeat/`, `recording/`, `security-view/` and `lock/`, each a folder with its own door. `door/` is the door MCP clients come in through, core code the plugins manager starts in a utility process of its own

`modules/` holds them: `wire.ts` makes them and `CoreModules` in `modules/modules.ts` starts them once as the plugins manager starts, hands them each change and answers the router's gate, guard, providers and flood control and the plugins manager's grant risk classifier, storage's clear, heartbeat and security view while each is on. Flood control, recording, the security view and the lock run on through shutdown and the stopped mode. Recording is made by `wire.ts` over boot's log and handed to the router and the plugins manager, the holder keeping its switch. A module switched off is closed where it has a close and one switched on again is started and handed what it needs. A start or a push that throws marks the module failed until one goes through, so its calls are refused and nothing stops. The fail-safe controls among them (the gate, flood control and the lock, the contract's `failSafeControls`) begin and get their first push alone first, one at a time, each with its start marker on disk from before its start until its first push returned (`starting` and `started` in what the plugins manager hands): one of them failed at start leaves every other module never begun or handed anything and puts hetu in the stopped mode. `modules/header.ts` is its door: the holder's shape, the states and records and what each module requires

`lib/` holds the logic two parts of the backend share: `data-dir.ts` (where hetu keeps its data, for boot and the runtime), `url.ts` (parsing a URL and checking it names a host alone, for the runtime's sessions and the fetch from GitHub) and `github.ts` (main's one way to the network, for the plugins manager's Install button and the updater). Each part's door is its `header.ts`, holding definitions only

`lib/github.ts` is a GET with Node's own fetch to `api.github.com`, `github.com` or `release-assets.githubusercontent.com` over https with no user or port (`onGitHub`). Each redirect is checked against the same hosts before it is followed (`redirect: 'manual'`, five at most). No cookie or credential is sent and every request names the client `hetu`. The byte cap is counted as read and refused early by a Content-Length past it. One time limit covers the request with its redirects and body. A failure answers one of `fetchProblems`, each with words the trusted window can show (`fetchProblemWords`): a 404 is `not-found`, which `readRelease` answers as `no-release` for the API, a 429 or a 403 with no requests left or a time to wait is `rate-limited` and a fetch or a body read that rejects is `offline`. `readRelease` asks the API for a repo's release, the latest or one by tag, and parses its tag and assets

`updater/` looks at hetu's latest full release on GitHub for an update file signed with the publisher's key, once the core is ready and every 7 days, in a locked build only, and installs one on the human's click. `main.ts` makes it and starts the installer just before the exit, see `updater/README.md`

`wire.ts` joins the core in its order: the core modules, recording over boot's event log, the gate module's actions, the router asking the modules for the gate, the guards, the providers and flood control, then the plugins manager, which calls the router and is never called back. It hands the router the parts serving a namespace under their names in the contract's namespace table: the runtime, recording and the gate module here, the plugins manager its own as it is built, then the plugins manager's table. The Electron entry calls it once boot is done. `routerOptions` builds what the router asks for, so the plugins manager's tests run the same wiring

`main.ts` is the Electron entry that joins the parts, see `runtime/README.md`

The file helpers the folders share are in `core/lib/disk.ts`
