The heartbeat, a core module in main that watches each running plugin for a hang. It sets how often a plugin is pinged and how many misses it takes, and asks the core to act. The ping, the pong, the mark and the kill stay the core's

- `heartbeat.ts`: `createHeartbeat`, made by `core/backend/wire.ts` and held by `core/backend/modules/modules.ts`, which opens it with what the plugins manager hands at start (`HeartbeatCore`: `ping`, `unresponsive`, `kill` and the limits) and closes it, every timer ended, when the human switches it off or hetu stops. The plugins manager tells it `started` once a plugin is ready, `heard` for anything heard from it and `stopped` when its incarnation ends. Every `heartbeatMs` it pings the plugin's half, and `heartbeatMisses` unanswered in a row ask the core to mark a worker `unresponsive`, whose calls then answer `timeout` at once while nothing is closed, or to kill a utility half, which then reads crashed with `unresponsive`. A check that throws is skipped with a `fault` and the next ping counts
- `header.ts`: its door, the shapes the plugins manager and the holder read

Switched off, nothing is pinged, marked or killed and a call to a hung plugin fails on its own deadline: the plugins manager reads every unresponsive plugin ready again. Switched on, it watches every plugin that runs. It is not a security control, so switching it off applies at once like any core module that serves. It imports no Node built-in. Its tests are in `core/test/heartbeat.test.ts`, the plugins manager's path in `core/test/plugins-manager-lifecycle.test.ts` and `core/test/plugins-manager-utility.test.ts`

Roles: `heartbeat.ts` monitor, since it detects a hang and asks the core to respond, `header.ts` contract
