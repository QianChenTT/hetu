Recording, a core module in main that writes what happens to the one event log boot opened. It enforces nothing: the caller on the same step decides whether to wait for a record to land

- `recording.ts`: `createRecording`, made by `core/backend/wire.ts` over boot's `EventLog`, handed to the carrier and the plugins manager. Its switch is in `switches.off`, read through `core/backend/modules/modules.ts` like every core module's, and it runs on through shutdown and the stopped mode. `coreRecord` and `coalesced` take the core's own records, `record` one a caller waits on, `call` each call's audit record, `failing` says whether the oldest record the audit queue holds waited `logFailMs` unwritten and `serve` answers `log.segments` and `log.verify` whatever the switch. It tells the log failing once, as records queue and once a second, until the plugins manager takes it, and tells the carrier when the log's health changed. `drain` and `resume` are for switching it off: what waits is written first, the switch's own record counts what still waits and is the last one written, and it applies even when that record is lost
- `records.ts`: the core record lane straight through the log with its bounded backlog, the coalesced core records and the bounded audit queue with `next` and `ack`
- `audit.ts`: `AuditWriter`, the writer of the audit queue: every 100 ms up to 256 records written as `audit.call` lines with one fsync, and `auditFields`, which maps a record to log fields with the hash it is handed for an exec command's `commandHash`
- `header.ts`: its door, the log it writes through, what a landing is and the shape the carrier and the plugins manager call

Switched off, nothing is taken in, every wait answers `muted`, the log never counts as failing and what the queue held is let go. Switching it off is a security control's switch, held for the trusted window's Confirm and typed with `recording`. A switches file from before it was a core module holds the old field for this switch, which is read once as `recording` in `off`. A throw in it is that record not landing: a caller waiting fails and hetu runs on. It imports no Node built-in: the join hands it the log and SHA-256. Its tests are in `core/test/recording.test.ts`, `core/test/audit-writer.test.ts` and the carrier's path in `core/test/carrier-records.test.ts`

Roles: `recording.ts` records, `records.ts` records, `audit.ts` records, `header.ts` contract
