The grant risk classifier policy job's core module, in main. The plugins manager hands it the whole table at every class change: every plugin with what it holds and what its entry stores, the change to one plugin with what it would hold, its cause and whether a Confirm for it is on screen. It answers for every plugin the change moves (the changed plugin and every entry whose links the change moves, every entry in a pass): the class from 0 to 4, the items that ask at their first use and the notice owed, with the lines the trusted window shows under the core's words and for an update whether it loads unasked. It walks the links itself, holds every class rule and makes no calls. The core checks every answer and keeps the fallback for when there is none

- **a grant's class:** `ui.*` but `ui.keystream`, `ui.edit` and `ui.read`, `storage`, `events.subscribe` and `plugin.call` itself 0. `ui.keystream`, `ui.read`, `luoshu.read` and `luoshu.list` 1. `luoshu.write` and `lock.set` 2, or 4 when its first path part holds a wildcard. `history` 2. `ui.edit` 2 on any scope, since each edit waits in the editor for the human's save. `net.fetch` 3, or 4 with `*`. `exec`, `guard.hook` and `log.read` 4
- **a plugin's class:** the highest of its grants and the grants it reaches through `plugin.call`, either way round, followed in turn. A subscription gives the plugin that hears none of the speaker's grants, so it never raises the listener's class
- **the pair rule:** a plugin is 4 when a read can reach it and it can reach network: it reads or a plugin upstream of it reads, and it holds network or a plugin downstream of it holds network, since together they could send notes out. Data moves along `plugin.call` both ways and along a subscription to another plugin's topics one way, from the plugin that owns the topic to the plugin that hears it, followed in turn through any mix of the two. With `plugin.call` alone that is reading and network anywhere in what the plugin reaches. Reading here counts `luoshu.read`, `luoshu.list`, `ui.read`, `ui.keystream`, `luoshu.write` and `history` read
- **first use:** the items whose own class is 4, and for a pair the items that close it: the plugin's network items, or with none the `plugin.call` items that bring the network in, and for a plugin that reads nothing itself the subscriptions a read moves in through
- **the screen:** the class and its name, what the plugin reaches through `plugin.call` and, for one with network, the plugins that read and are connected to it that way. Past `plugin.call`, one with network names the plugins that read and can reach it through events and one that reads names the plugins with network it can reach through events. A last line names the programs in its `exec` items that run other programs or code
- **the classes a change moves:** a change to one plugin can move its own class and the class of every plugin linked to it. A move up is shown on the Confirm of the request that causes it, by the plugin with the class it held and the one it moves to. A move down is stored without a line. A class not known counts as 4
- **updates:** an update loads unasked only for a plugin whose entry holds class 0, that the table as it stands still classes 0, whose new version asks for nothing it doesn't hold and that holds no type asking on every update (`ui.layout`)
- **the moves that alert:** a move up made with no Confirm on screen gets a notice of its own only where the class changes what hetu does, leaving 0, whose updates apply on their own, or entering 4, whose items ask at first use. A move inside 1 to 3 raises nothing

`grant-risk-classifier.ts` makes it, `decide.ts` answers a table, `walk.ts` follows the links over the table and `rules.ts` holds the class of each grant, the pair rule, the first-use items, the screen and the moves that show and alert. Its interface and the shape check on its answer are in `core/api/classes.ts`. `core/backend/wire.ts` makes it and the plugins manager asks it while it is switched on. Its tests are in `core/test/modules/grant-risk-classifier`
