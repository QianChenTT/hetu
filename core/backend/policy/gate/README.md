The gate, a core module in main that holds the gate policy job. It decides each call with power on the newest grants snapshot the plugins manager pushed: each plugin's grants as items, each with its switch and whether its first use asks. Windows are judged on `core/api`'s fixed window grants, never on the grants snapshot

`gate.ts` holds the logic: `decide` at the raw stage and the canonical one, asking at an item's first use, `canRead` and `canList` for events and listings and `stateChanged` for each new grants snapshot, with each grant's scopes compiled once per grants snapshot through `compileScopes`. `core/backend/wire.ts` makes it and `core/backend/modules/modules.ts` hands it each grants snapshot. A `stateChanged` that throws marks the gate failed until the next one goes through. `actions.ts` serves the gate's own actions, `gate.reach` and `gate.filterReadable`, which the router hands it as it hands any core action: off it gives back everything while a record can land, while the gate starts or is down it refuses `policy-down` and a throw refuses that one call with a fault. `gate.filterReadable` gets a view of the live call it names from the router and keeps how far a throttled call got with that view. It counts the gate's time each caller spends in a second, which the router charges listings to as well. `core/backend/wire.ts` makes it and hands it to the router under the part name `gate`. Its tests are in `core/test/modules/gate`
