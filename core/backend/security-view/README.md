The security view, a core module in main in the path of every security change a window asks for, as the gate is in the path of every call. The trusted window, its session and the sender check that make the window authentic stay the core's and can't be switched off

- `security-view.ts`: `createSecurityView`, made by `core/backend/wire.ts` and held by `core/backend/modules/modules.ts`. `asked` says whether a change applies at once with its record after (a narrowing), lands its record first and then applies (one the trusted window itself asks for with `confirmOff` on and no word to type) or waits for the trusted window's Confirm. `confirms` says whether a click counts: the request first in line for the input delay and, where `mustType` names a word, that word typed exactly. `mustType` asks for a security control's id to switch it off, recording's and its own included
- `header.ts`: its door, the shapes the plugins manager reads

The plugins manager keeps the queue, the fingerprint and the stale check, record-before-apply and applying, and `changeEffect` stays in the contract. Switched off, every change a window asks for applies unasked, its record first, a Confirm of a request the core raised counts at once with no word, and the editor window may send only the change that switches the view on again, which narrows and applies at once. Switching it off is asked in the trusted window and typed with `security-view`. A throw applies nothing and answers the page `failed`, which it shows, with a `fault` recorded. It runs on through shutdown and the stopped mode, so the stopped mode's choices wait for its Confirm. It imports no Node built-in. Dev mode is a group of its settings in the trusted window, the hash checks skipped, which plugins load unhashed and the unsigned builds trusted, with no code of its own. Its tests are in `core/test/security-view.test.ts` and the plugins manager's path in `core/test/plugins-manager-requests.test.ts`

Roles: `security-view.ts` policy holder, `header.ts` contract
