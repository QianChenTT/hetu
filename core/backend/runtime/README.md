The runtime, one of the four parts of the core and the only one that touches Electron. `main.ts` beside this folder is the Electron entry and joins the parts

- `before-ready.ts`: what must run before Electron's `ready`, all of it synchronous. A packaged build started with `--remote-debugging-port` or `--remote-debugging-pipe` exits first. Then the data folder, `userData` inside it so the single-instance lock follows the folder, the lock, the sandbox for every renderer and the `hetu` scheme registered once
- `sessions.ts`: one in-memory session per role: the editor, the trusted window and the workers. Each denies every permission, device and download, refuses every request but its own `hetu` hosts and serves those hosts' pages from the app with a CSP. The editor page may frame and show images from the views host. The default session refuses everything
- `views.ts`: the views host, each running plugin's frames and icons served from the bytes it started with. A frame loads once from a single-use `hetu://views/<token>/` under a CSP naming only that path, with no network, frames or forms and only the editor page as its parent. Its entry page is served once and no other page, so a frame that navigates finds nothing. Icons are `svg` or `png` from `hetu://views/icon/<plugin>/`. Tokens end with their incarnation and when the editor page unloads
- `windows.ts`: the guards on every web contents (no navigation a page starts, no new window, no webview, no Bluetooth pick), the web preferences every page gets, the editor window with the shell's preload and the trusted window on its own page with the same preload. `HETU_QUIET_WINDOWS=1` in a run from the source opens windows without focus on another display, as the tests run
- `electron.ts`: the loader's runtime on Electron. Channels are `MessageChannelMain` ports read the way the carrier reads a port. Workers start and end in the hidden renderer, host halves load through `hosts.ts`. Main's port reads only text within the plugin's cap
- `workers.ts`: the hidden renderers that hold the workers, one per community plugin and one the first-party plugins share, each opened when its first worker starts. A community plugin's renderer closes a moment after it holds nothing. Starts wait for a page to say ready, a renderer that dies is recorded with the plugins it held, and its window skips background throttling, since its workers answer heartbeats
- `drawer-ports.ts`: a channel for each pair of a running worker whose plugin holds a ui item and an editor page load, made once the page's `dom-ready` says its preload listens, one end to the worker host page and one to the editor page, named with the plugin and its incarnation. Messages then go renderer to renderer. A worker's end is told to the page, and a new load gets new pairs
- `window-way.ts`: a window's way into the carrier. Its messages come only on its own webContents' IPC and the sender check refuses all but its top frame, attached, on its own `hetu` host. Each load of the window is its own caller, `{ kind: 'window', role, n }`: a new document ends the old load's way, and an answer goes only to the load that asked
- `hosts.ts`: loads a host half from the bytes the loader hashed, as one `data:` module that can import only Node's built-ins. Its default export is its plugin, run on its link, and its role exports go to the carrier and the loader: `gate`, `guard`, `provider`, `watchdog`, `luoshu`, `capabilities`, `storage`, `history` and `exec`. The loader hands the luoshu and history the notes folder when each is ready and on every `luoshu.set`, and exec its view of the grants when it is ready and with every applied change. A role that throws marks its plugin failed
- `intrinsics.ts`: freezes the built-ins once, before the first host half loads, so a host half can't swap a method `core/api` decides with. `name`, `message`, `toString`, `valueOf`, `toLocaleString` and `constructor` stay settable on code's own objects
- `trusted.ts`: the one trusted window and its input delay: for a second after it shows or gains focus main drops its keyboard and mouse input, a key or button pressed meanwhile with its repeats and release included. A Confirm counts only once it armed
- `quit.ts`: Quit in its order, each step with a deadline, and relaunch. `main.ts` closes the windows a human sees first and ends the hidden renderer last, so workers stop while they still run. After a failure windows hear `core.quitting` and get a two second grace. `HETU_NO_RELAUNCH=1` in a run from the source exits without starting again, as the end-to-end tests run

`core/build/main.ts` bundles the entry into `core/dist/main.js` with the install list beside it, which names search and the layout as first-party copies built into `core/dist/plugins` and hidden-marks as an in-page plugin with its module bundled into `core/dist/plugins/hidden-marks`. A run from the source takes its install from there, or from `HETU_INSTALL_DIR`
