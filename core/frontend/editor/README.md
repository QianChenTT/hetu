The drawer: the editor window's page, core code. It holds the editor, the raw view, the views menu and the banner, takes the core keys before anything else, draws what plugins send and serves the editor bridge and the ui verbs at its end of each plugin's port. It holds no power of its own: its calls are the window's, through the window's way in, and a plugin reaches through it only what the gate gives that plugin

The page has three layers below the core layer's banner, bar, raw view and menu. The base layer holds the layout's skeleton, or the drawer's plain layout, every view in one column beside the editor, while no layout draws. The lifted layer above it holds every view, the frames, the titles and the editors, in that order upward, each laid over its placeholder and clipped to it, so no node of the layout's covers them or hears what happens in them. The overlay layer holds popovers: a popover takes no style of the plugin's, its body does, under a strip naming the owner by its id that no style moves or covers. Theme tokens reach the base and lifted layers only. Titles and strips name a plugin by its id, which no plugin can make read as hetu

- `preload.ts`: the window's only way to the core, `send` and `listen` on the window's IPC channel through the context bridge. Only the top frame gets it, so a frame in the window has no bridge. Main's ports to the drawer come through it too, named with the plugin and its incarnation, and reach the page by `window.postMessage`, since a port can't cross the context bridge
- `index.html`, `page.ts` and `shell.css`: the page. The core keys are taken in the capture phase: Ctrl+/ the raw view, Ctrl+S save and Ctrl+Q Quit. Ctrl+P is a plugin's to bind. Outside the editors a key goes to the focused view's own bindings, then the global ones. The raw view and the menu sit over everything in fixed styles, drawn as text and never markup. Drags run here on pointer events: a view's title onto the layout's zones, a node's payload onto a node that accepts it or a note's path onto an editor, a split's divider
- `link.ts`: the window's calls and events, shared by the parts below. Each event is acked once before any handler runs
- `shell.ts`: the banner from `core.status`, read again each time the core says so. Each request waiting is a notice naming the plugin it waits for, which opens the trusted window only once it has been on screen for the input delay. A button opens the plugin list
- `notes.ts`: the open notes, one instance with an opaque id per note, named by the path `luoshu.read` answered, where the note is, so two spellings of a note are one instance and a plugin's reach to it is judged on where it is, read through `luoshu.read` and saved through `luoshu.write` with the version read. A save names the plugins whose edits the text carries as `onBehalf`. `stale` keeps the text as a draft, so does `locked`, which names no holder. Take over clears the lock on that note alone as the window through `lock.clear`, then saves again, one click with no Confirm. A draft per note is kept in the window's storage space a second after the last change, on `core.quitting`, on a stale save and before a reload and offered back when the note opens. A save from outside reloads a clean buffer and leaves a dirty one with a notice
- `note-bar.ts`: the note bar's words and buttons for each notice and what a refusal means to the human, with no DOM so it runs in tests. A locked note's bar names no holder and offers Take over
- `editor.ts`: a CodeMirror view per open note, each laid over the editor slot the layout placed for it and hidden while none holds it. The current one is the note the human works in. A note saved with CRLF keeps it. A plugin's edit is its own undo step. CodeMirror's Mod-i is left out of its keys, so italic's key reaches the plugin bound to it. An Alt+click shows the hidden ranges of the element under the pointer and the text its widgets stand for, each plugin's innermost group there and only that plugin's, until no cursor is inside it. An element spans its group's marks, a line style its whole line. A Ctrl+click, Cmd+click on macOS, on a link mark's text goes to the drawer and is taken whole, so CodeMirror adds no cursor. Of the link marks holding the character clicked, every plugin's alike, the one with the smallest range wins and links of two plugins or two ids sharing that smallest range tell no one. A plain click places the caret as before. A link mark with a group widens that group's span for an Alt+click as any mark does
- `markdown.ts`: the markdown every editor parses notes with, GFM and `==highlight==`. What hides is a plugin's, such as hidden marks, a worker behind the bridge that the human installs. No plugin's code runs in the page
- `marks.ts`: marks drawn as CodeMirror decorations with the drawer's own classes. A plugin sends no class and no CSS. A link mark is drawn with the link class, underlined in the theme's accent color while it keeps 4.5 to 1 against the editor's background, else hetu's link color while that does, else the editor's text color. It hides or changes none of its text. Hidden text within a line is taken off the screen with a style and stays in the page, so an IME composing beside it reads the text right. A hidden range over a line break is replaced. A hidden range's group and edge ride on its decoration. A widget over a range replaces it and one at a point sits before the caret at its place, where typed text lands after it. A widget at a point strictly inside hidden text of its own plugin is left out, since nothing would show it or rest the caret there, one at the hidden text's edge drawn. A mark whose range CodeMirror refuses is left out alone, so the rest draw, and an error of any other kind is thrown
- `hidden-rules.ts`: the drawer's rules for hidden text, every plugin's and hidden marks' alike. The caret rests before hidden text, or after it and a widget opening the line when the hidden text starts its line, where Chromium puts typed text too. The arrows step to the next character the human sees, Backspace, Delete and every other key CodeMirror deletes with, the Mac's included, take only characters the human sees, a widget whole and a line hidden whole with one line break. Enter breaks the line after hidden markers that close and before those that open. A selection takes hidden text at its edges only with the whole element it belongs to, hidden text with no group belonging to its whole line. A caret a plugin's edit placed just after a closing marker stays there until the human types or moves. Text typed there goes there, where Chromium would put it before the hidden marker. Nothing runs during an IME composition
- `raw.ts`: which note the raw view shows: the focused instance's buffer, unsaved text included, else the note written last by anyone, with the ten written last to switch between. Whatever a plugin saved shows up here
- `keys.ts`: key names as the drawer compares them, so a binding and a key pressed meet however a plugin spelled the key. The core keys main reads before the page are in `core/api/keys.ts`
- `versions.ts`: each instance's changes counted from 0, the last 500 kept. A mark made for an older version is mapped to the text it was made for. An edit made for one is rebased through the changes since and refused `stale` only when it touches text changed since
- `surfaces.ts`: the trees the drawer keeps, one per owner and surface, each changed only by its owner's operations, at most 20 an owner
- `views.ts`: the view instances. The first of each declared view opens when its owner connects holding `ui.view`, the owner opens more, a crashed owner's first ones stay in place as down. The layout gets the manifest's title, never one set while running
- `ui-port.ts`: the ui half of each port: views drawn by their owners, the skeleton of the layout the human picked (else hetu's own, else the plain layout), `editor.open` inside the plugin's `luoshu.read` scope on the path it named and on the path the luoshu resolved, opening nothing and answering as for a note that couldn't be read when the second is outside, a frame's messages to its own worker, a view's own bindings and every event the human makes sent to the owner of the surface it happened in
- `draw.ts`: a tree drawn with the drawer's own elements, kept by node id so an input keeps its focus. A redraw writes only what changed and counts its writes. Styles go in as values with `style.setProperty`, hover, focus and pressed styles apply with no round trip, text is always text, a long list draws only its rows on screen. An image node shows a note's image from a URL main mints for each new element or path, which loads once. A load that fails asks for one new URL and no more. The plugin never sees the URL or the bytes and a frame's policy can't reach the host
- `layers.ts`: what each layer holds and where: views, frames, titles and editors over their placeholders, popovers next to their anchors, and what the layout plans from. Each owner's redraws are held to 20,000 writes to the page a second, the rest drawn in the next second
- `drag.ts`: the parts of a drag with no DOM: the zone under the pointer, where in it, a payload's checks, a split's sizes held to its minimums, a press becoming a drag
- `frames.ts`: view frames, sandboxed with scripts only, from a single-use URL main mints. A port on the first load, removed with `frame.navigated` recorded on any later one. A frame is inert behind a shield until the human clicks it and again after a press elsewhere, and one that takes focus on its own is closed until the window loads again. Messages are JSON text of plain data within 64 KiB, 100 a second, to and from the frame's own plugin's worker only. A frame runs in its own process, so one that loops forever leaves typing in the editor working
- `settings.ts`: the window's settings in its storage space: the layout and theme picked, favorites and the owners of keys two plugins bind
- `theme.ts`: a theme's tokens as CSS variables, the editor's colors held to 4.5 to 1 contrast or hetu's own
- `menu.ts`: the views menu, in the core layer
- `bridge.ts`: the drawer's end of each plugin's port. Main makes one for each plugin worker holding a ui item and each page load. Each message is a call shaped like CodeMirror (`editor.instances`, `read`, `decorate`, `edit`, `bind`, `keystream`, `viewports`), served only with what `gate.reach` says the gate gives the plugin for that note: reading, decorating and editing need its `luoshu.read` there, or its `ui.read` there on a note the human opened from a node of a plugin that reads or lists the note itself, by a click, a drop or Enter or Space on it, editing `ui.edit` there too and never `luoshu.write`, an edit placing the cursor only in answer to the command the human just invoked through the plugin's binding, on that note at the version the command named and inside the range the edit changed or at its edges, once per key and within a second, closed by a move of the caret, any other key, a binding changed or a refused edit with a cursor, decorating `ui.decoration`, bindings `ui.command` and the key stream `ui.keystream`. Events about a note go only to plugins that read it and the range its editor draws only to those that asked for it with `viewports`, checked at each send. What a plugin no longer reaches is taken back when the core says something changed and what it held goes when it ends. A key two plugins bind fires for neither until the human picks its owner in the views menu. A link click goes as `editor.link` with the note's version and the link's id only to the plugin whose link mark it landed on, while that plugin reads the note and holds `ui.decoration`, checked at the send. The click closes every window to place the cursor as the human's key does. Link marks count toward the same caps and throttles as other marks. The ui verbs go to `ui-port.ts` once the plugin holds the item each needs, draws throttled past 200,000 nodes looked at a second, a draw refused before it applies when its operations could pass that

Measured on a 2,000-line note (#73): from the character typed on screen to a worker's mark on it, a median of 1.2 ms and 2.0 ms at the 95th percentile, over the plugin's port and back
