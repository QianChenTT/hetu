Shared mechanism the core and the host halves import. Holds no state or policy. The core makes one `EventLog` and one `StateStore` per run, since a second log would fork the chain

- `event-log.ts`: the hash-chained event log, one line per event
- `disk.ts`: the file helpers the folders share. A short retry when Windows refuses a rename, delete or read because another program has the file open. Syncing a folder after a rename on macOS and Linux
- `hashed-file.ts`: the strict JSON parser and the hash line that ends each state file
- `hash-files.ts`: reads each file of a plugin folder once and hashes the bytes read, by path, size and content. Links and special files are refused. The plugins manager runs exactly the bytes hashed
- `clean-env.ts`: what history and exec share to run a program: an environment built from empty with only the variables named and never one that loads code, a program found by its real absolute path outside the folders a command may run nothing from, and one spawn with no shell, a hidden window, capped output and a deadline. On Windows the base holds the eleven variables a process start carries anyway, with a `PATH` of System32 alone
- `canonical.ts`: resolves a luoshu path the way the OS does through links, junctions and 8.3 short names. Refuses one that leaves the luoshu or reaches `.git`, any other dot folder or dot file or hetu's own folders. One spelled with no dot that reaches a dot name is refused with the same name as if missing beside it, which a provider that only reads acts on. `folderState` looks at a path's folder again just before a provider acts on it and `looked` resolves the caller's spelling once more for one that reads as moved, going on with the same key and the path judged or a path the gate allows. `named` does the same for a file a provider holds open, whatever its folder reads as: the caller's spelling resolved again has to hold the file opened, compared by its file id, at the path judged or a path the gate allows
