What builds hetu: the app from the source, the stage a package is made from and the package itself

- `main.ts`: `buildMain` bundles `backend/main.ts` into one ES module with `electron` left to the runtime, the core modules in `backend/policy` and `backend/providers` among it, each page and preload, the core plugins (`mcp-http-handler` and `hidden-marks`) with the list of their hashes and the first-party plugins the install carries: search and the layout from `core-plugins/`, the file explorer from the `hetu-plugins` package. `packaged` and `locked` are fixed into `main.js` as the two constants of `backend/runtime/packaged.ts`. `npm run build:main` writes `core/dist` for a run from the source
- `module-imports.ts`: `checkModuleImports`, which `buildMain` runs on the metafile of `main.js`. Each core module is the files under its folder in `moduleFolders` and everything they import, hetu's own `api` and `lib` included. It may reach only the Node built-ins on its list in `moduleBuiltins`, by the exact name it imports: the gate and the grant risk classifier none, storage `node:crypto`, `node:fs/promises` and `node:path`, the luoshu, history and exec their own. Anything else left to load at run time (`electron` among it), the plain ways past an import that `checkHostReach` finds in hetu's own files and a module folder with no file in the bundle fail the build
- `community.ts`: where a first-party plugin from the community repository comes from. `QianChenTT/hetu-plugins` is a dev dependency at one full commit, `github:QianChenTT/hetu-plugins#<commit>`, which npm fetches from GitHub into `node_modules/hetu-plugins`. npm ci follows `package.json` for a git dependency and checks no integrity for one, so `pinnedCommit` holds `package.json` and the lock to the same commit. `PIN` records that commit and the hash of what the build takes from the package at it: the package's `package.json` and the plugin's folder. `communitySource` builds from nothing else: a missing or linked package, a script npm runs on install, a manifest naming another id or other files fail the build with a plain message. Nothing of the package is run, its source is bundled with hetu's own SDK and the install list's hash is of what the build wrote. `writeFirstParty` in `main.ts` refuses the plugin before writing it when its bundle took in a file outside its folder and `core/sdk` and `core/api`, compared by real path and named in the message, so a module from anywhere else in the package or from hetu's own `node_modules` never reaches the install
- A change of the pin is a change of `package.json`, the lock and `PIN` together: `npm install --ignore-scripts --save-dev --save-exact github:QianChenTT/hetu-plugins#<commit>`, then the new hash in `PIN`, which the build's refusal names and which is checked against a clone of that commit before it is recorded
- `stage.ts`: `stageInstall` builds into a new empty folder: `app/` (`main.js`, the preloads, the pages, the install list and a `package.json` of its own), which becomes `app.asar`, and `plugins/`, which sits beside it. Nothing comes from the repo or `core/dist`, so no source, no `node_modules` and no plugin a build stopped writing can reach an install
- `fuses.ts`: `FUSES`, each of Electron's fuses as hetu sets it with its reason, and `fuseConfig` for `@electron/fuses` with every fuse required, so an Electron that adds one fails the build until it is decided here
- `package.ts`: `packageHetu` stages, runs electron-builder with its config in code, removes Electron's default app before electron-builder lists the archives for the executable's integrity, flips the fuses after the integrity of `app.asar` is in the executable and writes `SHA256SUMS` over the MSI. `executableIn` names the executable in a packed folder. The tool sits behind this one function and every proof tests what it made

The shipped build is packaged and locked: the list inside `app.asar`, the plugins beside it, no argument, no debugging switch, no environment switch and no DevTools. The build the end-to-end tests drive is packaged and not locked, with the inspector fuse left on, and is never made into an installer
