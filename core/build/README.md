What builds hetu: the app from the source, the stage a package is made from and the package itself

- `main.ts`: `buildMain` bundles `backend/main.ts` into one ES module with `electron` left to the runtime, the core modules in `backend/policy` and `backend/providers` among it, each page and preload, the utility bootstrap as `utility.js` and the door (`backend/door/host.ts`) as `door.js` beside `main.js`, the door importing only the Node built-ins `doorNode` in `core/api/ids.ts` names. A `hetu-install.json` or `plugins/` an older build left in the output goes. `packaged` and `locked` are fixed into `main.js` as the two constants of `backend/runtime/packaged.ts`. `npm run build:main` writes `core/dist` for a run from the source
- `notices.ts`: the third-party notices. `buildMain` reads every bundle's metafile, takes each package an input sits in under `node_modules` once and writes `THIRD_PARTY_NOTICES.txt` beside `main.js`, inside `app.asar`: each package's name, version, license and the license text it ships, since the bundles keep no license comments. A package that ships no license file takes the text of its SPDX id from `licenses/` (`Apache-2.0.txt`, for `@humanwhocodes/momoa`), and one with neither fails the build
- `module-imports.ts`: `checkModuleImports`, which `buildMain` runs on the metafile of `main.js`. Each core module is the files under its folder in `moduleFolders` and everything they import, hetu's own `api` and `lib` included. It may reach only the Node built-ins on its list in `moduleBuiltins`, by the exact name it imports: the gate and the grant risk classifier none, storage `node:crypto`, `node:fs/promises` and `node:path`, the luoshu, history and exec their own. Anything else left to load at run time (`electron` among it), the plain ways past an import that `checkHostReach` finds in hetu's own files and a module folder with no file in the bundle fail the build
- `stage.ts`: `stageInstall` builds into a new empty folder: `app/` (`main.js`, `utility.js`, `door.js`, the preloads, the pages, `THIRD_PARTY_NOTICES.txt` and a `package.json` of its own), which becomes `app.asar`. Nothing comes from the repo or `core/dist`, so no source, no `node_modules` and nothing a build stopped writing can reach an install
- `fuses.ts`: `FUSES`, each of Electron's fuses as hetu sets it with its reason, and `fuseConfig` for `@electron/fuses` with every fuse required, so an Electron that adds one fails the build until it is decided here
- `package.ts`: `packageHetu` stages, runs electron-builder with its config in code, removes Electron's default app before electron-builder lists the archives for the executable's integrity, flips the fuses after the integrity of `app.asar` is in the executable and writes `SHA256SUMS` over the MSI. `executableIn` names the executable in a packed folder. The tool sits behind this one function and every proof tests what it made

The shipped build is packaged and locked: the door inside `app.asar` with `main.js` and nothing beside it, no argument, no debugging switch, no environment switch and no DevTools. The build the end-to-end tests drive is packaged and not locked, with the inspector fuse left on, and is never made into an installer
