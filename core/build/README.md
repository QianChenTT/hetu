What builds hetu: the app from the source, the stage a package is made from and the package itself

- `main.ts`: `buildMain` bundles `backend/main.ts` into one ES module with `electron` left to the runtime, each page and preload, the install plugins with the list of their hashes and the first-party plugins the install carries. `packaged` and `locked` are fixed into `main.js` as the two constants of `backend/runtime/packaged.ts`. `npm run build:main` writes `core/dist` for a run from the source
- `stage.ts`: `stageInstall` builds into a new empty folder: `app/` (`main.js`, the preloads, the pages, the install list and a `package.json` of its own), which becomes `app.asar`, and `plugins/`, which sits beside it. Nothing comes from the repo or `core/dist`, so no source, no `node_modules` and no plugin a build stopped writing can reach an install
- `fuses.ts`: `FUSES`, each of Electron's fuses as hetu sets it with its reason, and `fuseConfig` for `@electron/fuses` with every fuse required, so an Electron that adds one fails the build until it is decided here
- `package.ts`: `packageHetu` stages, runs electron-builder with its config in code, removes Electron's default app, flips the fuses after the integrity of `app.asar` is in the executable and writes `SHA256SUMS` over the MSI. `executableIn` names the executable in a packed folder. The tool sits behind this one function and every proof tests what it made

The shipped build is packaged and locked: the list inside `app.asar`, the plugins beside it, no argument, no debugging switch, no environment switch and no DevTools. The build the end-to-end tests drive is packaged and not locked, with the inspector fuse left on, and is never made into an installer
