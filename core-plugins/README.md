One package per plugin with one manifest and one identity. Its entries say where each half runs: `worker` in a hidden renderer and `frames` in a window. Core plugins may also have `page` in a window and `host`, which runs in a utility process of its own. The manifest names `requires` and `provides`, core plugins also `guards` and `node`. The core plugins built so far are mcp-http-handler and hidden-marks. The watchdog, leases and net are designed and not built. The gate, the grant risk classifier, storage, the luoshu, history and exec are no plugins: they are core modules in `core/backend/policy` and `core/backend/providers`, bundled into `main.js`. The event log is the core's own. Hidden marks runs in-page, compiled into the editor page from the install. CodeMirror is the editor window's own, no plugin. The layout runs sandboxed today. Git, artifacts and MCP are designed to and aren't built

`layout/` is hetu's own layout, built on `@hetu/sdk` and tested on its fake core and its fake drawer. Search and the file explorer are community plugins hetu doesn't ship: the human installs them from a local folder. A plugin may declare `views` drawn as trees or frames and a `theme` of token values in its manifest. `mcp-http-handler/` is the agent door, a host half in its utility process. `hidden-marks/` holds the manifest of the in-page plugin whose module the editor page compiles in
