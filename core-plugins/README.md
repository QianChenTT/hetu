One package per plugin with one manifest and one identity. Its entries say where each half runs: `worker` in a hidden renderer and `frames` in a window. Core plugins may also have `host`, which runs in a utility process of its own. The manifest names `requires` and `provides`, core plugins also `guards` and `node`. The core plugin built so far is mcp-http-handler. The watchdog, leases and net are designed and not built. The gate, the grant risk classifier, storage, the luoshu, history and exec are no plugins: they are core modules in `core/backend/policy` and `core/backend/providers`, bundled into `main.js`. The event log is the core's own. CodeMirror is the editor window's own, no plugin. The layout and hidden marks run sandboxed today. Git, artifacts and MCP are designed to and aren't built

`layout/` is hetu's own layout, built on `@hetu/sdk` and tested on its fake core and its fake drawer. Search and the file explorer are community plugins hetu doesn't ship: the human installs them from a local folder. A plugin may declare `views` drawn as trees or frames and a `theme` of token values in its manifest. `mcp-http-handler/` is the agent door, a host half in its utility process. `hidden-marks/` is hidden marks, a first-party worker behind the editor bridge
