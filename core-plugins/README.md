One package per plugin with one manifest and one identity. Its entries say where each half runs: `worker` in a hidden renderer and `frames` in a window. Core plugins may also have `page` in a window and `host`, which runs in a utility process of its own. The manifest names `requires` and `provides`, core plugins also `guards` and `node`. The core plugin built so far is mcp-http-handler. The watchdog, leases and net are designed and not built. The gate, the grant risk classifier, storage, the luoshu, history and exec are no plugins: they are core modules in `core/backend/policy` and `core/backend/providers`, bundled into `main.js`. The event log is the core's own. CodeMirror is the editor window's own, no plugin. Search, the layout, the file explorer and hidden marks run sandboxed today. Git, artifacts and MCP are designed to and aren't built

`search/` is first-party search and `layout/` hetu's own layout, both built on `@hetu/sdk` and tested on its fake core, the layout on its fake drawer too. The file explorer isn't here: it lives in `file-explorer/` of the community repository `QianChenTT/hetu-plugins`, which hetu's build takes as a dev dependency at one pinned commit and builds as a first-party plugin with hetu's own SDK (`core/build/README.md` says how the commit is pinned and moved). A plugin may declare `views` drawn as trees or frames and a `theme` of token values in its manifest. `mcp-http-handler/` is the agent door, a host half in its utility process. `hidden-marks/` is hidden marks, a first-party worker behind the editor bridge
